# Профильные модели на полном TwiBot-22 — 23 ноября 2026

Обучение на всех 1 000 000 профилях TwiBot-22 с официальным разбиением:
train 700 000 (ботов 7,8 %), val 200 000 (28,0 %), test 100 000 (29,4 %).
Гиперпараметры и ранняя остановка выбирались только по val (PR-AUC), порог — по лучшему F1 на val.
Test в каждом запуске читается один раз, после того как все конфигурации зафиксированы.
Модель `review-mvp-v1` сохранена для отката.

## Наборы признаков

- **baseline5** — пять профильных признаков модели `review-mvp-v1` (подписчики, подписки, их отношение, наличие описания и аватара).
- **portable** (profile-v2, 17 признаков) — поля, которые есть и в профиле Threads: подписчики, описание (наличие, длина, ссылки, упоминания, хэштеги, доля цифр), аватар и аватар по умолчанию, имя и username (длины, доли цифр и спецсимволов, цифры в конце, подчёркивания, совпадение имени и username).
- **twitter** — portable и 13 признаков, которые есть только в Twitter: подписки, число твитов и списков, возраст аккаунта, частоты в день, локация, ссылка, закрытость, закреплённый твит.

Верификация намеренно исключена (см. «Аудит»). Возраст аккаунта считается от самой поздней даты создания аккаунта в наборе: эта дата служит оценкой момента сбора.

## Аудит переобучения и утечек (portable-XGBoost)

| Проверка | Результат |

| Кривая обучения: 10 % / 30 % / 100 % train | val ROC-AUC 0,699 / 0,700 / 0,700 |
| 5 seed, полный train | std ROC-AUC 0,00004, std PR-AUC 0,00009 |

| Пересечение ID между частями | 0 |
| Профили val/test, совпадающие с профилем из train | 3,3 % / 5,6 %; метка большинства совпадает в 55 % |

Переобучения нет: на отложенной части train качество то же, что на обучающей. Рост данных не улучшает модель: качество ограничено признаками.
Разрыв train → val (0,85 → 0,70) объясняется различием частей TwiBot-22, а не запоминанием: в train ботов 7,8 %, в val/test 28–29 %; описание заполнено у 92 % аккаунтов train и у 76–79 % в val/test.

**Верификация.** Все 95 398 верифицированных аккаунтов находятся в train и размечены как люди; в val и test их нет. Признак учил правило, которое нельзя проверить, а в Threads верификацию (Meta Verified) можно купить. После удаления признака test ROC-AUC portable-XGBoost изменился с 0,743 до 0,742.

**Отсутствие полей Threads** (test ROC-AUC при замене поля пропуском): все поля — 0,742; без аватара по умолчанию — 0,740; без имени — 0,739; без описания — 0,713.

## Выводы

1. Решают признаки, а не алгоритм: три ансамбля различаются в третьем знаке; логистическая регрессия отстаёт на 0,015–0,02 ROC-AUC.
2. Признаки, доступные только в Twitter, добавляют около 0,015 ROC-AUC к переносимому набору.
3. Переносимые признаки имени и username почти не меняют ROC-AUC, но поднимают точность верхушки очереди (первые 1000: 0,70 → 0,83–0,85).
4. Точность 85 % держится только на короткой очереди: несколько сотен — полторы тысячи аккаунтов (2–5 % ботов теста).
5. На test результаты выше, чем на val (ROC-AUC ≈ +0,04): разбиение TwiBot-22 неоднородно, поэтому в работе приводятся обе оценки.
6. Accuracy не используется как основная метрика: доля ботов в train в 3,6 раза ниже, чем в val/test.

Качество на Threads этими экспериментами не подтверждено.

## Рабочий артефакт profile-review-v2

`scripts.build_profile_v2_model` упаковывает portable-XGBoost (ModelService поддерживает XGBoost) в `media/models/review-profile-v2/`.
Деревья не переобучались; добавлена медианная импутация, обученная на train.
Порог 0,4543 — максимальный recall при precision ≥0,70 на val: очередь 6,1 % val, recall 15,2 %.
На test при том же пороге: очередь 8,7 %, precision 78,3 %, recall 23,1 %.
Для оценки нужны минимум подписчики, описание, username и имя; без них — `insufficient_data`.
