# Межаккаунтные признаки: graph-v6

Эксперимент использует одинаковые train/val аккаунты и bottom100 постов. Общий raw читается целиком и проверяется по SHA256, но признаки извлекаются только для выбранных train/val записей. Test не оценивается. Повторное извлечение требуется потому, что v5 сохранил агрегаты, а не идентичность общих объектов. V6 сохраняет хешированные объекты в отдельном локальном token cache для последующих экспериментов.

## Построение

Четыре группы объектов: точная раскрытая URL (без fragment), ID адресата, URL+UTC10минутный интервал, адресат+такой интервал. Query сохраняется; сокращатели повторно не раскрываются. SHA256 токены используются только как ключи сравнения и никогда как числовые признаки.

Окружение — только train. Для train удаляется сам аккаунт, для val ищутся совпадения с train. Ни validation observations, ни какие-либо labels не изменяют train reference. Популярные объекты с>60train участниками исключаются. Для каждого канала: доля объектов, имеющих другого участника, log1p числа соседей с≥2разными общими объектами, максимум совпадающих объектов с одним соседом и этот максимум/число query объектов. Один общий объект не считается повторной связью. Это агрегаты наблюдаемой коактивности, не доказательства автоматизации.

Train и val имеют слегка разную доступность reference из-за удаления self; крупные бакеты ограничены по train total membership. Признаки зависят от состава окружения, размеров выборки и неполной истории. Совпадения по10минутным бакетам чувствительны к границам; близкие события по разные стороны границы не совпадут. Отсутствие совпадений не означает отсутствия координации.

## Проверка

Фиксированные profile+graph и profile+metadata-v5+graph, XGBoost300/depth4/lr.05/seed42, imputer train only, без подбора параметров. Сравнение top2520validation с прежней моделью. Прогнозы сохранённых моделей проверяются после reload. Артефакты research-only, не поддерживаются активным feature schema; деплой не выполняется.

Запуск: `.venv/bin/python -m scripts.graph_experiment`. Данные в media/models/experiments/graph-v6/. Завершённый token cache можно использовать после проверки identity и SHA256; прерванный raw pass не поддерживает автоматический resume. Завершённая оценка не перезаписывается.

## Итог, проверен 22 ноября 2026

| Модель | Ботов в очереди2520 | Ложных срабатываний | Precision | Recall |
|---|---:|---:|---:|---:|
| Активный профиль |1522|998|60.40%|19.86%|
| Профиль + связи |1455|1065|57.74%|18.98%|
| Профиль + metadata + связи |1427|1093|56.63%|18.62%|

Улучшения нет. Активную модель не заменяли. Признаки повторных общих URL доступны у5.03%train и3.68%val; URL+время —0.65%train и0.53%val; targets+время —13.88%train и8.00%val. Различие покрытия может влиять на перенос между выборками, но этим экспериментом причинность не установлена. Повторные targets без времени распространены (80.01%/67.02%), однако массовость сама по себе не делает признак полезным для классификации.

22ноября повторно проверены SHA256 моделей/token cache, загружены обе модели, полностью воспроизведены validation-очереди. Проверки graph/metadata:8passed. Исходный scan выполнялся до усиления cache guard; формулы и параметры fit не менялись. Это отражено в [финальном JSON](2026-11-22-graph-v6-final.json).

Серия v3–v6 не показала пользы усложнения на этом фрагменте. Следующий обоснованный этап — новые данные с более полным покрытием и независимая разметка Threads. До их появления сохранять профильный MVP для ограниченной ручной проверки, не объявлять его полноценным детектором Threads. Повторный перебор графовых порогов на той же validation увеличит риск подгонки; новый контроль нужен до новых выводов о качестве.
