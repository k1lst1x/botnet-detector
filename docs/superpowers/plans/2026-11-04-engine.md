# Threads engine preparation Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task by task.

**Goal:** Prepare TwiBot-22 data and a tested Django → FastAPI → worker → features/inference path without training.
**Architecture:** Pure Python/Pydantic domain; streaming data preparation; offline XGBoost commands; SQLAlchemy job store and Celery workers behind authenticated FastAPI. Django owns users and CRM job references.
**Tech Stack:** Python, Django 5.2, FastAPI, SQLAlchemy, PostgreSQL/SQLite, Celery/Redis, PyArrow, ijson, sklearn, XGBoost.
**Spec:** plans/2026-11-04-threads-bot-detection.md (approved by user on 2026-11-04).

## Global Constraints

- No training runs, including synthetic training tests. Training code is prepared but fit is not executed.
- No live Threads collection without credentials; imports and fixture transports must work now.
- Unknown values stay null; UTC timestamps; no TF-IDF or semantic language features in new core.
- Keep official train/val/test; do not refit on test; no automatic training from inference.
- Raw and prepared datasets remain ignored by Git.

## Review Focus

- Truncated/search timelines must not produce misleading frequency features.
- Duplicate IDs and conflicting labels must fail instead of overwriting data.
- Tenant isolation must hold even when job IDs are known.
- Worker retries and duplicate submissions must not create duplicate analyses.
- Missing/corrupt/incompatible models must not become heuristic probabilities.
