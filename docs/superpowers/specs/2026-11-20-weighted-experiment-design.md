# Аудит смещения и второй эксперимент

Пользователь согласовал следующий шаг: исследовать train/val и эксперимент с весами классов. Сохраняем существующие признаки, выборки, seed и параметры XGBoost. Единственное изменение fit — scale_pos_weight = human_train / bot_train. Это технический выбор исполнителя для изолированной проверки влияния дисбаланса; коррекция prior сама по себе не гарантирует качество ранжирования.

Альтернативы: менять признаки одновременно (невозможно выделить эффект весов); перебрать множество весов (повышает риск подгонки validation); один train-derived вес (выбран). Аудит сравнивает пропуски, квантили и KS effect size train/val отдельно по классам и суммарно, без p-values и без чтения test. Аудит не доказывает причин смещения или переносимости на Threads.

Второй fit использует прежний pipeline и frozen protocol. Порог выбирается только по validation, precision goal 0.9 и минимум 100 positive predictions. Сравнение двух запусков на одной val является исследовательским, не независимой оценкой обобщения. Test уже просмотрен в первом запуске и не перечитывается. Деплоя и автоматической маркировки пользователей нет. Сохраняются конфигурация, хеши, отчёт, локальный артефакт. Новый Threads holdout требует реального экспорта/API; синтетические данные его не заменяют.
