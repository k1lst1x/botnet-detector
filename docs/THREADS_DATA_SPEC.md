# Техническое задание: сбор публичных данных Threads

Версия 1.0, 24.11.2026

## 1. О задаче

Дипломный проект: система, которая находит скоординированные группы ботов в соцсетях. Модель обучена на данных Twitter. Чтобы проверить её на Threads, нужен небольшой набор публичных постов и профилей Threads.

**От исполнителя требуется** собрать данные по этому ТЗ и сдать их в описанном формате (п. 7).
**Не требуется** анализировать данные, определять ботов или размечать аккаунты.

Группы ботов видны только там, где несколько аккаунтов действуют вокруг одних и тех же постов. Поэтому собираются **ветки обсуждений целиком**, а не случайные аккаунты.

## 2. Порядок сбора

1. По каждой теме из п. 3 найти исходные посты, у которых 20 и больше ответов.
2. Для каждого исходного поста выгрузить все доступные ответы, ответы на ответы и цитаты.
3. Для каждого автора из этих веток выгрузить профиль.
4. Если источник позволяет, выгрузить до 50 последних постов для случайных 20 % авторов.
5. Повторить выгрузку тех же веток и профилей через 1, 3, 7 и 14 дней после первой. Это нужно, чтобы увидеть удалённые аккаунты, изменения профилей и всплески активности.

## 3. Что собирать

### 3.1. Темы

| Группа | Темы | Доля веток |
|---|---|---|
| Основная | политика и выборы (в том числе Казахстан); криптовалюта, инвестиции, «заработок», ставки, казино; реклама, скидки, розыгрыши; вирусные посты знаменитостей и брендов; громкие новости и ЧС | ~70 % |
| Контрольная | еда, спорт, кино, учёба, бытовые вопросы | ~30 % |

Контрольная группа обязательна. Языки: русский, казахский, английский. Каждую тему взять из 10–15 разных веток, а не из одной большой.

### 3.2. Типы постов

| Тип | Признак | Собирать |
|---|---|---|
| Исходный пост | нет родительского поста | да |
| Ответ | есть родительский пост | да, это основной материал |
| Цитата | пост цитирует другой пост | да |
| Репост | репост другого поста | если источник отдаёт |
| Пост со ссылкой | внешняя ссылка в тексте или карточке | да, ссылку сохранить |
| Пост с медиа | фото, видео, карусель | да, но сохранить только тип медиа, файлы не скачивать |

### 3.3. Что не собирать

Закрытые аккаунты, личные сообщения, сами медиафайлы. Не собирать ничего, для чего нужен вход в чужой аккаунт.

## 4. Поля

**О** — обязательно, **Ж** — желательно. Если значение неизвестно или источник его не отдаёт, писать `null`. Не писать вместо него 0 или пустую строку: для модели это разные вещи. Пустая строка допустима, только если поле действительно пустое (например, у пользователя нет описания).

### 4.1. Профиль — файл `accounts.jsonl`

| Поле | Тип | | Описание |
|---|---|---|---|
| `user_id` | string | **О** | числовой id аккаунта в Threads, а не username |
| `username` | string | **О** | без `@` |
| `display_name` | string | **О** | отображаемое имя |
| `biography` | string | **О** | описание профиля; `""`, если пустое |
| `followers` | int | **О** | число подписчиков |
| `profile_picture_url` | string | Ж | ссылка на аватар |
| `avatar_default` | bool | Ж | стоит ли стандартный аватар |
| `is_verified` | bool | Ж | галочка верификации |
| `is_private` | bool | Ж | закрытый ли аккаунт |
| `likes_7d`, `replies_7d`, `reposts_7d`, `quotes_7d`, `views_7d` | int | Ж | счётчики за 7 дней, если доступны |
| `collected_at` | string | **О** | момент выгрузки профиля, UTC, ISO 8601 |
| `snapshot` | int | **О** | номер повторной выгрузки: 0, 1, 3, 7, 14 |
| `source` | string | **О** | `threads_api`, `manual` или название сервиса |

### 4.2. Пост — файл `posts.jsonl`

| Поле | Тип | | Описание |
|---|---|---|---|
| `post_id` | string | **О** | id поста |
| `author_id` | string | **О** | `user_id` автора |
| `author_username` | string | **О** | username автора |
| `created_at` | string | **О** | время публикации, UTC, ISO 8601 |
| `text` | string | **О** | полный текст |
| `parent_post_id` | string | **О** | на какой пост это ответ; `null` для исходного поста |
| `parent_author_id` | string | **О** | автор родительского поста |
| `root_post_id` | string | **О** | исходный пост ветки; у исходного поста — его собственный id |
| `quoted_post_id` | string | **О** | цитируемый пост или `null` |
| `reposted_post_id` | string | Ж | исходный пост репоста или `null` |
| `post_type` | string | **О** | `root`, `reply`, `quote`, `repost` |
| `mentions` | list[string] | **О** | username упомянутых через `@`; `[]`, если упоминаний нет |
| `urls` | list[string] | **О** | все внешние ссылки поста; `[]`, если ссылок нет |
| `media_type` | string | Ж | `text`, `image`, `video`, `carousel` |
| `topic_tag` | string | Ж | тег темы Threads |
| `likes`, `replies`, `reposts`, `quotes` | int | Ж | счётчики на момент выгрузки |
| `permalink` | string | **О** | ссылка на пост |
| `topic` | string | **О** | тема из п. 3.1 |
| `group` | string | **О** | `main` или `control` |
| `collected_at` | string | **О** | момент выгрузки, UTC |
| `snapshot` | int | **О** | номер повторной выгрузки |

### 4.3. Журнал — файл `collection_log.csv`

Одна строка на каждый запрос или выгрузку ветки. Колонки:
- `timestamp`;
- `source`;
- `query` — поисковый запрос или ссылка на исходный пост;
- `topic`;
- `snapshot`;
- `items_received`;
- `truncated` — выдача обрезана лимитом или нет;
- `complete` — ветка выгружена полностью или нет;
- `error` — текст ошибки или пусто.

Если ветку не удалось выгрузить полностью, это нужно записать сюда, а не умалчивать.

## 5. Объём и сроки

| Показатель | Минимум | Цель |
|---|---|---|
| Темы | 10 | 20 |
| Ветки (исходные посты) | 100 | 300 |
| Посты | 5 000 | 20 000 |
| Уникальные авторы с профилем | 2 000 | 8 000 |
| Период повторных выгрузок | 7 дней | 14 дней |

У официального Threads API есть суточные лимиты: около 2200 поисковых запросов и около 1000 запросов профиля. На 8000 профилей уйдёт минимум 8 суток, это нужно учесть в плане сбора. Перед стартом исполнитель присылает короткий план: источник, сроки, ожидаемый объём.

## 6. Источники и правила

1. Приоритет источников: официальный Threads API → ручной сбор → сторонние сервисы и скрейперы. Сторонний сервис можно использовать только после согласования с заказчиком: автоматический сбор без API противоречит условиям Meta.
2. Собираются только публичные данные.
3. Данные не передаются третьим лицам и не публикуются. Обработка персональных данных ведётся в соответствии с Законом РК «О персональных данных и их защите».
4. Ключи доступа и пароли не попадают в сдаваемые файлы.

## 7. Что сдаётся

```
threads_dataset/
├── accounts.jsonl
├── posts.jsonl
├── collection_log.csv
├── raw/              # ответы источника без изменений (JSON/HTML), разложенные по датам
├── checksums.txt     # SHA256 всех файлов
└── README.md         # источник, даты, инструменты, известные проблемы
```

Кодировка UTF-8, в каждой строке файлов `.jsonl` один JSON-объект, все времена в UTC.

Сдача в два этапа:
1. **Пилот:** 10 веток в первой выгрузке. Заказчик проверяет формат.
2. **Полный набор:** после того как заказчик подтвердит пилот.

## 8. Критерии приёмки

- [ ] Все обязательные поля присутствуют; неизвестные значения записаны как `null`.
- [ ] `user_id` — числовой id, а не username, минимум у 95 % авторов.
- [ ] У каждого ответа заполнены `parent_post_id` и `root_post_id`. По этим полям ветка восстанавливается до исходного поста.
- [ ] Минимум у 80 % авторов есть профиль с `username`, `display_name`, `biography`, `followers`.
- [ ] Нет дублей `post_id` внутри одной выгрузки.
- [ ] Основная и контрольная группы в соотношении примерно 70/30.
- [ ] Повторные выгрузки сделаны для тех же веток и помечены `snapshot`.
- [ ] Журнал заполнен, обрезанные и неполные выгрузки отмечены.
- [ ] Сырые ответы источника сохранены, контрольные суммы сходятся.
